# M2 Results: XGBoost Models for Player Props

**Date:** 2026-02-20
**Status:** Complete

## Overview

Trained one XGBoost regressor per stat category using 193 walk-forward-safe features from the M1 feature engine. Evaluated against a rolling-10-game-average baseline on both validation (2024-25) and held-out test (2025-26) sets.

## Data Splits

| Split | Seasons | Rows (played only) |
|-------|---------|-------------------|
| Train | 2022-23, 2023-24 | 55,782 |
| Val | 2024-25 | 28,198 |
| Test | 2025-26 | 16,690 |

651 DNP rows excluded (dnp == 0 filter). No min-minutes or min-games filter at training time.

## Hyperparameters

Sensible defaults, no grid search. Early stopping on val set (30 rounds patience).

```python
n_estimators = 500
learning_rate = 0.05
max_depth = 5
min_child_weight = 10
subsample = 0.8
colsample_bytree = 0.7
reg_alpha = 0.1
reg_lambda = 1.0
```

### Key Takeaways from Feature Importance
- **Rolling averages dominate** — the player's own recent history is by far the strongest signal
- **Longer windows (10, 20) outweigh shorter (3, 5)** — smoothing reduces noise
- **FGA is critical for points** — shot volume predicts scoring more than shooting efficiency
- **is_starter appears in every model** — starter status is a meaningful signal for all stats
- **Opponent features have low importance** — opp_* features don't crack the top 10 for any stat; opponent matchup context may need richer features (e.g., position-specific) to matter
- **Schedule features (rest, B2B) have low importance** — the model doesn't find these very predictive on their own

## Honest Assessment

### What's Working
- All P0 models beat the rolling-average baseline on both val and test sets
- No overfitting: test results are consistent with val
- Calibration is monotonic — the model's confidence correlates with accuracy
- When the model has a strong opinion (top/bottom quintile), it's right ~60% of the time
- For betting, you only need ~52.4% at -110 juice, so 57-58% directional accuracy is viable

### What's Underwhelming
- **4-5% MAE improvement is modest** — the rolling average is a strong baseline that's genuinely hard to beat without external data
- **Opponent features aren't contributing** — they don't appear in top features for any stat, suggesting the current opponent representation (team-level rolling averages) isn't granular enough
- **Blocks model fails** — too noisy/low-variance for the current feature set
- **three_pm directional accuracy is below 50% on test** — the model may be overfit to val patterns for three-pointers

### Improvement Paths (Prioritized)

1. **Minutes projection model** (high impact)
   - Minutes is the #1 upstream driver of all stats
   - A separate model predicting minutes (from starter status, rest, matchup, etc.) could be used as an input feature
   - Currently the model uses rolling average of minutes, which doesn't account for lineup changes

2. **Injury and lineup data** (high impact)
   - A teammate being out reshuffles usage entirely
   - The model has no way to know about injuries, DNPs, or load management
   - Even basic "is the team's #1 scorer playing?" would help

3. **Real prop lines** (high impact for profitability, not accuracy)
   - Currently using roll_mean_10 as a proxy line
   - Real PrizePicks/Underdog lines may be softer or harder in different spots
   - Collecting actual lines is critical for M4 backtesting

4. **Richer opponent features** (medium impact)
   - Current: team-level defensive averages
   - Better: position-specific or minutes-tier-specific opponent stats
   - e.g., "how do opposing guards score against this team?"

5. **Hyperparameter tuning** (medium impact)
   - Currently using sensible defaults, no search
   - Bayesian optimization (Optuna) over learning_rate, max_depth, min_child_weight
   - Could squeeze another 1-2% improvement

6. **Pace-adjusted features** (low-medium impact)
   - Normalize stats by estimated game pace
   - A player in a fast-paced game has more possessions = more opportunities

7. **Interaction features** (low impact, speculative)
   - Player × opponent interactions
   - Home/away × rest interactions
   - May be learned implicitly by tree models already

## Reproduction

```bash
# Train P0 stats (points, rebounds, assists)
uv run python -m models_ml.train

# Train all stats (P0 + P1)
uv run python -m models_ml.train --all-stats

# Evaluate on val set
uv run python -m models_ml.evaluate

# Evaluate on test set
uv run python -m models_ml.evaluate --split test --all-stats
```

Saved models: `models_ml/saved/{stat}_model.joblib`
Each bundle contains `{"model": XGBRegressor, "metadata": {...}}` with feature columns, params, and metrics.
